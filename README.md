# StreamClipper 2.0

**StreamClipper** — программа для Windows, в которую вы просто кидаете **ссылку
на канал** (Twitch и YouTube). Программа проверяет канал каждую секунду: как
только стример выходит в эфир, она **сама автоматически заходит на стрим** —
подключается к записи, читает чат, находит момент, когда чат «взрывается», и
вырезает клип **ровно 60 секунд** с субтитрами прямо **во время трансляции**.

Готовый клип прилетает **уведомлением на любое устройство** (Telegram, ntfy,
Bark, Pushover, webhook), появляется в **веб-приложении** — на телефоне и ПК:
скачали видео — оно исчезло с экрана и осталось в **«Загруженном»** (кнопка
в углу экрана) — и **сам публикуется в TikTok** с хэштегами (если подключили).

Каналы добавляются **ОДИН раз с сайта** (кнопка «Каналы» на телефоне) — программа
следит за ними всегда, перезапуск не нужен. Если на стриме началась реклама
(RubAp / RubUp) — **нарезка ставится на СТОП и сама продолжается после неё**.
Настроили ОДИН раз на компьютере — и всё работает постоянно (есть автозапуск).

Всё работает полностью локально: никаких чужих серверов — только ваш ПК,
платформы и ваши каналы уведомлений.

## Что внутри

- **Вертикальный формат TikTok 9:16** — каждый клип **1080×1920**: стрим
  по центру во всю ширину, сверху/снизу — размытый фон, субтитры в нижней
  зоне, баннер — по центру. Ровно 60 секунд — сразу готов для TikTok.
- **Максимальное качество** — запись идёт **без перекодирования** (`copy`),
  в том качестве, в котором ведёт стример (1080p60, 1440p — как есть),
  финальный клип кодируется с высоким качеством (crf/CQ 18–19).
- **Клип ровно 60 секунд** — 30 с до пика хайпа + 30 с после (`clip.total: 60`).
- **Максимально быстрый процесс**:
  - выход в эфир замечается за ~3–5 с (быстрые API платформ);
  - буфер пишется сегментами по 2 с — границы клипа точные;
  - финальная обработка на видеокарте (авто-выбор NVENC → Intel QSV → AMD AMF,
    иначе быстрый x264) — клип готов за считанные секунды после пика;
  - речь распознаёт faster-whisper в быстром режиме (`beam_size: 1`).
- **Субтитры — ТОЛЬКО из речи человека**: faster-whisper распознаёт голос и
  игнорирует чат (чат не отслеживается — по требованию). Стиль как на образце:
  **жирный КАПС двумя строками внизу по центру** — верхняя строка **белая**,
  нижняя — **жёлтая**. Есть и классический стиль с плашкой (`subtitle.style: classic`).
- **Рекламный баннер RubUP в каждой нарезке** (banner.mp4):
  - **нарезка ставится на паузу**, пока идёт ролик RubUP: кадр стрима замирает,
    звук стрима молчит; после окончания рекламы эфир продолжается дальше;
  - баннер идёт **со звуком** (звук самого ролика RubUP);
  - занимает **~30% площади экрана** (правило рекламодателя: минимум 25%);
  - стоит **по центру кадра** — не в углу;
  - ролик проигрывается **целиком**; в клипе длиннее минуты — **раз в минуту**
    (наши клипы ровно 60 секунд — один показ);
  - другой баннер = просто заменить файл **banner.mp4** рядом с программой,
    перезапускать не нужно.
- **Уведомления на любое устройство**: Telegram (видео прямо в чат до 50 МБ),
  ntfy, Bark (iPhone), Pushover, webhook — или сразу на все (`provider: all`).
- **Автопостинг в TikTok**: готовый клип сам выкладывается в TikTok через
  случайную паузу (антибан) с описанием и хэштегами — режимы «окно Chrome
  с вашим входом» и «официальный TikTok API» (подробности ниже).
- **Пауза нарезки во время рекламы (RubAp / RubUp)**: когда на стриме начинается
  реклама, новые клипы НЕ снимаются, а после её окончания нарезка продолжается
  сама. Серверная реклама ловится автоматически (маркеры в HLS-плейлисте),
  рекламу поверх эфира помечают кнопкой «РЕКЛАМА» на сайте. Сегменты,
  записанные во время рекламы, в клипы не попадают.
- **Веб-приложение для телефона и ПК** (index.html + app.js + style.css —
  оно же сайт на GitHub Pages): лента эфиров со статусами LIVE, список готовых
  клипов с превью, скачивание в один тап, кнопка **«Загруженное» в углу экрана**,
  всё адаптировано под iPhone 12 (safe-area, тач-цели, тёмная тема). Работает
  **офлайн**: сервис-воркер (sw.js) кэширует весь сайт, скачанные клипы хранятся
  копиями в приложении — «Смотреть» и повторное «Скачать» доступны даже без сети.

## Как это работает

```
Вы кидаете ссылку на канал (шторка «Каналы» на сайте / links.txt / бот)
   |
   v
Слежка постоянно                <- проверка «в эфире?» каждые 2–4 сек
   |                              (внутренние API платформ, без ключей)
   v  стример вышел в эфир
Подключение НЕМЕДЛЕННО:         <- не ждём конца стрима!
   запись потока в кольцевой буфер (ffmpeg, копия исходного потока, ~5 мин)
   + чтение чата в реальном времени (Twitch IRC / YouTube live chat)
   |
   v  чат взорвался (всплеск, КАПС, KEKW/КЛИП-спам, смех)
Клип = 30 сек до пика + 30 сек после = РОВНО 60 секунд    <- режется во время эфира
   |
   v
Субтитры: Whisper слышит РЕЧЬ -> жирный капс (белая/жёлтая строка) внизу
Баннер RubUP: нарезка НА ПАУЗЕ (кадр заморожен, звук стрима молчит),
   ролик RubUP со звуком по центру (~30% экрана) -> эфир продолжается
   |
   v
Уведомление на любое устройство + клип в веб-приложении
   -> нажали «Скачать» -> видео у телефона -> исчезло со списка -> «Загруженное»
   -> TikTok-автопостинг: клип сам уходит в TikTok (пауза 1-5 мин, антибан)
```

Пока на стриме идёт РЕКЛАМА — новые клипы не снимаются; после неё нарезка
продолжается автоматически (подробнее: раздел «Реклама RubAp / RubUp»).

## Клипы — вертикальный формат TikTok 9:16

Каждая нарезка по умолчанию готовится **ВЕРТИКАЛЬНОЙ — 1080×1920 (9:16)**,
как в TikTok: исходный кадр стрима стоит по центру во всю ширину, сверху и
снизу — размытое продолжение этого же кадра (классический стиль TikTok).
Субтитры (жирный капс, белая/жёлтая строка) ложатся в нижнюю зону и не
перекрываются интерфейсом TikTok, рекламный баннер RubUP — по центру кадра
(~30% площади). Клип ровно 60 секунд — публикация без какой-либо обработки.

Настройка (config.yaml → clip):
```yaml
  vertical: true          # 9:16 включён по умолчанию (false — горизонтальные)
  vertical_mode: blur     # blur — фон из размытого видео | crop — обрезка краёв
```

## Качество клипов: субтитры без пропусков и только сочные моменты

**Субтитры.** Распознавание идёт «лестницей попыток» (subtitle.py):
мягкий VAD (не съедает речь на фоне шума игры) → beam 5 → нормализация
громкости (loudnorm) + АВТООПРЕДЕЛЕНИЕ ЯЗЫКА. Язык по умолчанию «auto» —
клипы у зарубежных стримеров (автопоиск берёт топ всего Twitch) больше не
теряются из-за жёсткого «ru». На карточке каждого клипа и в уведомлении
видно, что распозналось: бейдж «СУБ RU 62%» = язык + доля речи.

**Отбор моментов.** В эфире: адаптивный порог (тихий чат не ждёт «больших
эфиров»), мгновенный триггер на явный взрыв (многократный всплеск + восторг
в большинстве сообщений), расширенные ключевые слова и эмоуты (KEKW, POG,
смех, КАПС), «гарантированный» клип берёт самый горячий момент последних
4 минут с весом восторженных сообщений. В нарезке видео: записи Twitch
дополнительно СКАЧИВАЕТ ЧАТ-РЕПЛЕЙ и выбирает окна, где чат смеялся и
спамил (а не просто «громко»), окна с полным отсутствием речи пропускаются
в пользу более говорящих (настройка на сайте).

**Управление с сайта** («Каналы» → «Качество клипов»): язык субтитров
(авто/ru/en), строгость отбора (точнее/стандарт/чаще), пропуск клипов без
речи. Кнопки **Интересно / Скучно** на карточке: «Скучно» повышает порог
каналу (меньше клипов, точнее), «Интересно» — понижает. Настройки и оценки
доезжают до бота экспорт-кодом (кнопка «Синхронизировать» → код в чат Z.ai).
В Actions всё применяется без перезапуска: Monitor перечитывает настройки
раз в минуту.

## Установка (Windows 10/11)

### Шаг 1. Python

Установите Python 3.10–3.12 с [python.org/downloads](https://www.python.org/downloads/).
Во время установки поставьте галочку **Add python.exe to PATH**.
Проверка: `python --version`.

### Шаг 2. ffmpeg

```
winget install Gyan.FFmpeg
```

После установки **закройте и снова откройте** консоль: `ffmpeg -version`.

### Шаг 3. Зависимости

В папке проекта запустите **install.bat** — он создаст окружение и поставит
все библиотеки (streamlink, yt-dlp, faster-whisper и остальные).

### Шаг 4. Ссылки на каналы — главный шаг

Откройте **links.txt** и вставьте ссылки на каналы — по одной в строку:

```
twitch.tv/ник
https://www.twitch.tv/ник
https://www.youtube.com/@имя_канала
https://www.youtube.com/channel/UCxxxx
https://www.youtube.com/watch?v=VIDEO_ID     (прямая ссылка на трансляцию)
```

- Можно просто **ник без ссылки** — считается Twitch.
- То же самое можно вписать в `channels:` в **config.yaml**.
- Файлы правятся **прямо во время работы** — программа подхватит изменения.
- Ещё способ: **пришлите ссылку боту в Telegram** — добавится сама.

### Шаг 5. Уведомления на любое устройство

В `config.yaml` раздел `notify`:

| Устройство | Что заполнить | Где взять |
|---|---|---|
| Telegram (рекомендуется) | `telegram.bot_token` + `telegram.chat_id` | @BotFather → /newbot; chat_id — напишите боту, откройте `api.telegram.org/bot<ТОКЕН>/getUpdates` |
| ntfy (Android/iOS/десктоп) | `ntfy.topic` | приложение ntfy → придумайте уникальный topic |
| Bark (iPhone) | `bark.device_key` | приложение Bark → скопируйте ключ из ссылки |
| Pushover | `pushover.user_key` + `api_token` | pushover.net |
| Свой сервис | `webhook.url` | POST JSON с клипом |

- `notify.provider: telegram` — один канал; **`provider: all`** — разослать клип
  на **все** заполненные каналы сразу (любое устройство получит уведомление).

### Запуск

Двойной клик по **run.bat**. Программа напишет адрес веб-интерфейса
(`Веб-интерфейс: http://IP:8765`) — он понадобится для телефона.
Enter в консоли — снять клип немедленно, Ctrl+C — выход.

## Автопостинг в TikTok (само выкладывается)

Готовый клип ставится в очередь и выкладывается в TikTok сам: описание собирается
из заголовка стрима + хэштегов (`tiktok.hashtags`), между публикациями —
случайная пауза 1–5 минут против блокировок.

Сначала проверьте настройку БЕЗ выкладывания: `tiktok.dry_run: true` —
в лог пишется «выложил бы ...», а в консоль ничего не публикуется.

### Режим browser (проще всего)

1. В Chrome на [tiktok.com](https://www.tiktok.com) войдите в свой аккаунт.
2. Установите расширение **«Get cookies.txt LOCALLY»** и экспортируйте cookies
   со страницы tiktok.com в файл **tiktok_cookies.txt** рядом с программой.
3. В config.yaml: `tiktok.enabled: true`, `mode: browser`.
4. На компьютере должен быть установлен Chrome — программа сама откроет окно,
   зайдёт под вашим аккаунтом, вставит клип, опишет и нажмёт «Опубликовать».
5. Если TikTok покажет капчу — окно ждёт (`captcha_wait: 90`), решите её руками.

### Режим api (официальный TikTok Content Posting API — надёжнее)

1. [developers.tiktok.com](https://developers.tiktok.com) → Create app →
   подключите продукт **Content Posting API** (scopes: video.upload, video.publish).
2. В config.yaml впишите `client_key` и `client_secret`; Redirect URI
   `http://localhost:8321/callback` пропишите и в настройках приложения.
3. Запустите **tiktok_auth.bat** (двойной клик) или `python tiktok_auth.py` →
   откроется браузер → войдите в TikTok →
   токен сохранится в tiktok_tokens.json (потом обновляется автоматически).
4. `mode: api`, `enabled: true`.

**Про публичные посты**: цель настроена — `privacy: PUBLIC_TO_EVERYONE`, клипы
выходят с лучшими хэштегами (#fyp #рек #стрим + игровые по названию стрима).
Но TikTok сам ограничивает неаудированные приложения: пока аудит не пройден,
API принимает только приватный режим, а с публичным аккаунтом отклоняет пост
целиком. Поэтому: подайте приложение на аудит (developers.tiktok.com → Products →
Content Posting API → Direct Post → Apply; privacy policy и terms уже лежат на
сайте: privacy.html и terms.html) — после одобрения система САМА начнёт
публиковать клипы ПУБЛИЧНО: очередь `tiktok_pending.json` разгрузится
автоматически, без ручных действий.

Соблюдайте правила TikTok и авторские права стримеров при автопубликации.

### Подключение TikTok прямо с сайта (без консоли)

В Настройках сайта есть поле **TikTok access_token** и кнопка **«TikTok»**:
вставьте токен, полученный в developers.tiktok.com, нажмите — токен сохранится
в tiktok_tokens.json, и автопостинг включится **сразу, без перезапуска**
программы. Статус («подключён, опубликовано N, в очереди M») виден в шторке
«Каналы».

## Реклама RubAp / RubUp во время эфира: нарезка на СТОП

Когда на стриме начинается реклама, **нарезка ставится на стоп**, а после её
окончания **продолжается автоматически**:

- **Автоматически** ловится серверная реклама: программа читает тот же
  HLS-плейлист, из которого пишет поток, и ищет маркеры
  (`twitch-stitched-ad`, SCTE-35 `CUE-OUT` и др. — список можно расширить
  в config.yaml → `ad.markers`).
- **Рекламу, которую стример включает сам поверх эфира** (RubAp / RubUp и
  подобные) в плейлисте не видно — её помечают с сайта: у эфира кнопка
  **«РЕКЛАМА»** (в шторке «Каналы» и в верхней ленте). Один тап — нарезка
  на паузе, второй тап — продолжение. Состояние видно всем устройствам.
- Сегменты буфера, записанные во время рекламы, **не попадают в клипы**:
  клип собирается только из чистых кусков эфира.
- Настройки — config.yaml:

```yaml
ad:
  enabled: true    # пауза нарезки во время рекламы
  poll: 4          # как часто проверять плейлист, сек
```

## Автозапуск: настроил ОДИН раз — работает всегда

На компьютере запустите **autostart.bat** (один раз) — StreamClipper будет
сам стартовать при каждом входе в Windows: следит за каналами из links.txt,
нарезает клипы, выкладывает в TikTok. Телефон в это время просто открывает сайт.

- Убрать автозапуск: `schtasks /Delete /TN "StreamClipper" /F`
- Консоль программы нужна только для логов — её можно свернуть.
- Если консоль закрыли случайно — запустите run.bat, слежка продолжится
  (список каналов сохранён в links.txt, настройки в config.yaml).

## ВСЁ ТОЛЬКО НА GITHUB: без компьютера вообще

Репозиторий может работать **САМ**: GitHub Actions проверяет каналы ПОСТОЯННО
(каждые ~25 секунд — задача слежения живёт 55 минут и передаётся эстафетой),
включает запись, когда стример вышел в эфир, режет клипы 60 секунд (9:16)
с субтитрами и баннером, заливает их в **Releases** и обновляет
**clips.json** — а сайт (GitHub Pages) показывает клипы и отдаёт их на
телефон. Ссылки на видео YouTube, записи и клипы Twitch тоже режутся:
задача **Clip video** сама находит интересные минуты (по громкости) и
нарезает длинное видео даже на ~100 вертикальных клипов. TikTok-автопостинг тоже выполняется внутри Actions — официальный
Content Posting API, ключи лежат в секретах репозитория.

### Настройка один раз (≈10 минут)

1. Создайте **ПУБЛИЧНЫЙ** репозиторий (public — Actions работает без лимита
   минут; в приватном лимит 2000 минут/месяц).
2. Распакуйте **StreamClipper-GitHub.zip** и загрузите **все файлы** в
   репозиторий, включая папку **.github** (в ней workflows — без неё
   автоматика не заработает).
3. Settings → Pages → **Deploy from a branch** → main / **(root)** → Save —
   через минуту сайт живой.
4. Settings → Actions → General → разрешите workflows (по умолчанию включено).
5. TikTok (необязательно): Settings → Secrets and variables → Actions →
   **New repository secret**: `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`,
   `TIKTOK_REFRESH_TOKEN` — откуда брать, см. «Откуда брать данные».
6. Каналы: на сайте → **Каналы** → вставьте ссылку (Twitch-канал, видео
   YouTube или клип Twitch). Без токена канал сохранится на устройстве —
   нажмите «Синхронизировать каналы» и пришлите код в чат ассистенту;
   с токеном ссылка уходит в репозиторий сразу. Либо правьте
   **subscriptions.json** прямо на github.com (карандаш → Commit changes).

Дальше всё само: каждые 5 минут «Check live» смотрит, кто в эфире → стример
вышел в эфир → «Monitor» следит до ~4,7 часов и нарезает клипы → клипы
появляются на сайте и уходят в TikTok → эфир кончился → снова проверка.

### Автопоиск лучших стримов Twitch

Бот и сам находит, кого резать: раз в ~20 минут он заходит на Twitch и берёт
в слежку **ТОП ЭФИРОВ ПО ЧИСЛУ ЗРИТЕЛЕЙ** (публичный GQL сайта, без ключей и
регистрации) — до 25 стримеров с отсечкой 2000 зрителей. Список живёт в
отдельном ключе `auto_channels` в **subscriptions.json**: ваши каналы в
`channels` никогда не трогаются и не удаляются, автопоиск только добавляет.
Настроить/выключить — раздел `discovery:` в config.yaml (`enabled: false` =
следим только за тем, что добавили вы).

### Как это выглядит в Actions

- **Check live** — короткая задача каждые 5 минут: обновляет статусы каналов
  в clips.json (их показывает LIVE-полоска на сайте) и запускает Monitor.
- **Monitor** — длинная задача: запись эфира, клипы по хайпу чата, релизы,
  clips.json, TikTok.
- **Releases** — вкладка с готовыми клипами (файлы, ссылки для сайта).
- **Слежение не обрывается**: сессия Monitor при окончании сама делает
  финальную проверку — если эфир продолжается, запускает новую сессию
  (цепочка до конца стрима). Плюс два независимых входа по расписанию:
  Check live каждые 5 минут и резервный Monitor каждые 30 минут — даже
  если одно из расписаний GitHub задержит, второе подхватит.

### Отличия от режима «на компьютере»

| | На ПК (run.bat) | На GitHub (Actions) |
|---|---|---|
| замечает выход в эфир | ~2–4 секунды | до 5 минут (шаг проверки GitHub) |
| клип появляется на сайте | секунды после пика | 2–5 минут (запись → субтитры → заливка) |
| уведомления о клипах | Telegram/ntfy/Bark из config.yaml | те же каналы через секреты NOTIFY_* (см. «Уведомления») |
| TikTok | API или Chrome-окно | только API (секреты) |
| YouTube «подтвердите, что не робот» | редко мешает | может мешать; Twitch — надёжно |

## Откуда брать данные (всё в одном месте)

| Что | Где взять | Куда ввести |
|---|---|---|
| Ссылки на стримеров | скопируйте адрес канала: twitch.tv/ник, youtube.com/@канал | Сайт → «Каналы» (или subscriptions.json на github.com) |
| GitHub-токен («Каналы» с телефона) | github.com → Settings → Developer settings → **Fine-grained personal access tokens** → Generate new token → имя любое (например `streamclipper`) → **Expiration: No expiration** (иначе через месяц всё сломается) → Repository access: **Only select repositories** → ваш репозиторий → Permissions: найдите в списке **Contents** → **Read and write** (остальные пункты не трогайте — Metadata включится сам) → **Generate token** → сразу скопируйте `github_pat_…` — показывается ОДИН раз | Сайт → Настройки → «GitHub без компьютера» → вставить → Сохранить |
| TikTok client_key / client_secret | developers.tiktok.com → Log in → **Manage apps** → **Create app** → продукт **Content Posting API** (scopes: video.upload, video.publish) → вкладка Key | Репозиторий → Settings → Secrets and variables → Actions → `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` |
| TikTok refresh_token (один раз, на ПК) | в config.yaml впишите client_key/client_secret → двойной клик **tiktok_auth.bat** (или `python tiktok_auth.py`) → войдите в TikTok → в появившемся tiktok_tokens.json скопируйте refresh_token | Репозиторий → Secrets → `TIKTOK_REFRESH_TOKEN` |
| Telegram / ntfy / Bark (необязательно) | BotFather / приложения ntfy, Bark | config.yaml → notify (режим ПК) или секреты NOTIFY_* (режим GitHub) |
| ntfy topic (самый простой пуш) | App Store / Google Play → приложение **ntfy** → «+» → подписка на уникальный топик (например `sc-и-случайные-буквы`) | Репозиторий → Secrets → `NOTIFY_NTFY_TOPIC` |

Без TikTok-секретов всё остальное работает: клипы появляются на сайте, но не
публикуются в TikTok. Ключ `privacy: PUBLIC_TO_EVERYONE` уже стоит: клипы не
аудированного приложения TikTok выкладывает только в приватный режим, а с
публичным аккаунтом отклоняет — нужен аудит приложения (после одобрения
публикации становятся публичными автоматически, отложенная очередь
разгружается сама).

## Уведомления: пуш, когда клип готов

В режиме GitHub уведомления включаются секретами репозитория (Settings →
Secrets and variables → Actions → New repository secret). Клип готов → Monitor
отправляет пуш во ВСЕ заполненные каналы сразу:

| Секрет(ы) | Что это |
|---|---|
| `VAPID_PRIVATE_KEY` | **Пуши прям с сайта, без сторонних приложений**: в Настройках сайта кнопка «Пуши на устройство». iPhone: сначала Safari → Поделиться → «На экран „Домой“», открыть с иконки, нажать кнопку. Подписки лежат в push_subscriptions.json, ключ уже записан в секрет |
| `NOTIFY_NTFY_TOPIC` | ntfy: приложение ntfy (iPhone/Android/десктоп), подписка на этот топик. Проще всего: без аккаунта. Клипы ≤ 14 МБ приходят прямо с видео во вложении |
| `NOTIFY_TELEGRAM_BOT_TOKEN` + `NOTIFY_TELEGRAM_CHAT_ID` | Telegram-бот пришлёт ВИДЕО прямо в чат (≤ 50 МБ). Токен от @BotFather; chat_id — через getUpdates |
| `NOTIFY_BARK_DEVICE_KEY` | Bark (iPhone): ключ из приложения Bark |
| `NOTIFY_PUSHOVER_USER_KEY` + `NOTIFY_PUSHOVER_API_TOKEN` | Pushover |
| `NOTIFY_WEBHOOK_URL` | любой webhook (POST c JSON) |
| `NOTIFY_NTFY_SERVER` | необязательно: свой сервер ntfy (по умолчанию https://ntfy.sh) |

В режиме ПК те же каналы настраиваются в config.yaml (раздел `notify`).

## Как сейчас работает сайт

- **Подключён к ПК** (Настройки → адрес сервера): лента обновляется каждые
  4 секунды, статусы каналов, кнопка «РЕКЛАМА», TikTok-токен, уведомления.
- **Открыт на GitHub Pages без ПК**: сайт читает clips.json рядом с собой —

  Releases, «Загруженное», офлайн-режим (сервис-воркер).
- **Токен на сайте — только для правки каналов** (добавить/убрать): репозиторий
  публичный, просмотр клипов и списка каналов работает и с ПУСТЫМ полем токена.
  Если GitHub отвечает «токен не принят (401)» — в Настройках вставьте токен
  заново, ВСЮ строку целиком (классический начинается с `ghp_`), без пробелов:
  сайт подхватит его и после кнопки «Сохранить». Список каналов при испорченном
  токене всё равно показывается — чтение уходит анонимно.
- Режимы можно совмещать: ПК — скорость, GitHub — работает всегда, даже когда
  компьютер выключен.

## Сайт: телефон + ПК + GitHub Pages (офлайн)

Файлы сайта лежат **плоско, без папок, прямо в корне репозитория** — рядом
с программой. Это один и тот же набор файлов и для GitHub Pages, и для
веб-сервера программы: `index.html`, `style.css`, `app.js`, `sw.js`,
`manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`.

### Способ 1 (самый простой): открыть с компьютера по Wi-Fi

1. Телефон и ПК — в одной Wi-Fi сети.
2. На iPhone откройте адрес из консоли: `http://IP-КОМПЬЮТЕРА:8765`.
3. Всё работает: статусы эфиров, клипы, скачивание, «Загруженное».
   (На Windows при первом открытии разрешите доступ в брандмауэре; если
   заблокировало — команда от администратора:
   `netsh advfirewall firewall add rule name="StreamClipper" dir=in action=allow protocol=TCP localport=8765`)

### Способ 2: сайт на GitHub Pages (работает офлайн, на телефоне и ПК)

Весь проект **плоский — все файлы в корне, без папок**, поэтому создаёте
репозиторий и перетаскиваете ВСЕ файлы из архива разом:

1. Создайте новый репозиторий на GitHub (например, `narejem`).
2. Нажмите **«uploading an existing file»** и перетащите **все файлы из
   архива** (index.html, style.css, app.js, sw.js, manifest.webmanifest,
   иконки, все .py-файлы, config.yaml, links.txt, requirements.txt,
   install.bat, run.bat, banner.mp4, README.md, LICENSE) — все файлы кладутся
   в корень, папок нет.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch →
   Branch: `main`, Folder: `/ (root)` → Save.**
4. Через минуту сайт будет на `https://ВАШ_НИК.github.io/ИМЯ_РЕПО/` —
   он откроется **на телефоне и на ПК**, а благодаря sw.js — **даже офлайн**
   (сервис-воркер кэширует оболочку сайта при первом открытии).
5. В Safari нажмите «Поделиться» → **«На экран „Домой“»** — StreamClipper
   откроется как приложение (своё имя и иконка уже настроены).
6. Подключение к ПК:
   - В **той же Wi-Fi** введите в настройках сайта `http://IP-ПК:8765`.
     Учтите: страница GitHub Pages работает по **https** и не может обращаться
     к **http**-серверу (mixed content) — сайт это честно подскажет.
   - Поэтому для GitHub Pages поднимите **бесплатный https-туннель** на ПК:

     ```
     winget install Cloudflare.cloudflared
     cloudflared tunnel --url http://localhost:8765
     ```

     Cloudflared выдаст адрес вида `https://xxxx.trycloudflare.com` — введите
     его в настройках веб-приложения (или в `server.public_base_url` в
     config.yaml). Тогда клипы будут скачиваться **откуда угодно**.

**Важно понимать**: сайт на GitHub — это интерфейс. Нарезка идёт на вашем ПК
(run.bat): ПК пишет стрим, режет клипы, вшивает субтитры и баннер. Сайт лишь
показывает готовые клипы и качает их с ПК (напрямую по Wi-Fi или через туннель).

### Как пользоваться веб-приложением

- Верхняя лента — каналы, за которыми следим (LIVE, зрители, уровень хайпа,
  метка **РЕКЛАМА**, если сейчас реклама).
- Карточки — готовые клипы (превью, канал, время, размер, «🔥 хайп»).
- **«Скачать»** — видео сохраняется на телефон и **исчезает со списка**.
- Кнопка **«Загруженное» в углу экрана** — всё, что вы скачали; оттуда можно
  скачать снова или вернуть клип в общий список. Список хранится на
  устройстве (localStorage), поэтому переживает перезагрузку страницы.
- Кнопка **«Каналы» в шапке** — управление слежкой с телефона (см. ниже).

### Каналы: добавил ОДИН раз — следит всегда (с телефона)

Шторка **«Каналы»** (иконка в шапке сайта) — главный пульт:

1. Вставьте ссылку `twitch.tv/ник` или `youtube.com/@канал` → **«Добавить»**.
2. Канал сохраняется в **links.txt** на компьютере — переживёт перезапуск.
   Программа следит за ним **постоянно** и сама зайдёт на стрим, как только
   он выйдет в эфир.
3. Статусы прямо в шторке: LIVE · зрители · уровень хайпа · РЕКЛАМА.
4. **Кнопка РЕКЛАМА** у эфира — «началась/кончилась» (см. раздел ниже).
5. «✕» убирает канал из слежки.

То же самое работает в Telegram: пришлите боту ссылку — добавится и тоже
сохранится навсегда.

### Что внести на сайте, чтобы ВСЁ публиковалось автоматически

| Шаг | Где | Что ввести | Сколько раз |
|---|---|---|---|
| 1 | Настройки (шестерёнка) | **Адрес сервера** из окна программы на ПК | 1 раз |
| 2 | Каналы (иконка в шапке) | **Ссылки на стримеров** | по 1 разу на канал |
| 3 | Настройки → поле **TikTok access_token** → кнопка **«TikTok»** | токен Content Posting API | 1 раз |

После шага 3 сайт ответит «TikTok-токен сохранён — автопостинг включён» и
**каждый готовый клип будет публиковаться в TikTok сам**: ровно 60 секунд,
субтитры внизу, баннер RubUP, хэштеги #fyp #foryou #рек #стрим #клипы (список
меняется в config.yaml → `tiktok.hashtags`). Публиковаться будет в «Только я»,
пока приложение TikTok не пройдёт аудит (см. раздел «Автопостинг в TikTok»).

## Частые проблемы

| Симптом | Решение |
|---|---|
| ffmpeg не найден | Шаг 2; после установки перезапустите консоль |
| «Нет ни одной ссылки» при старте | Вставьте ссылки в links.txt (Шаг 4) |
| Телефон не открывает http://IP:8765 | ПК и телефон в одной Wi-Fi; разрешите порт 8765 в брандмауэре (команда выше) |
| С GitHub Pages клип не скачивается | Страница https, сервер http — поднимите cloudflared-туннель (см. выше) и укажите его адрес в настройках сайта |
| TikTok: «cookies просрочены» | экспортируйте tiktok_cookies.txt заново из браузера с залогиненым TikTok |
| TikTok: капча в окне | решите её руками в открытом окне (программа ждёт `captcha_wait` секунд) |
| TikTok api: «init отказал» | не выданы scopes video.upload/video.publish или не запущен tiktok_auth.py |
| Telegram не приходит | Заполните bot_token и chat_id; сначала напишите боту сами |
| YouTube: «Sign in to confirm…» | `youtube.cookies_from_browser: chrome` в config.yaml |
| Клипы без субтитров | `pip install -r requirements.txt` (нужен faster-whisper); субтитры появляются только там, где человек говорил |
| Первый клип «думает» долго | Whisper скачивает модель один раз (~460 МБ) |
| Клип обрывается раньше 60 с | Хайп случился в первые секунды эфира — клип начинается с момента подключения; буфер `recorder.buffer_keep` ≥ 90 с |
| Нарезка «зависла», клипов нет | Возможно, идёт реклама: в ленте метка РЕКЛАМА или кнопка активна — тапните «Реклама кончилась», если реклама уже прошла |
| Реклама не ловится автоматически | Серверная реклама ловится маркерами; поверх-эфирную (RubAp/RubUp) помечайте кнопкой РЕКЛАМА на сайте |
| В логе «Площадь баннера меньше 25%» | увеличьте `banner.area` (по правилам рекламодателя минимум 25) |
| В логе «У banner.mp4 НЕТ звуковой дорожки» | правила требуют баннер со звуком — проверьте файл |
